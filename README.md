# CrySync

CrySync 是一个用 Go 编写的加密备份与同步服务。标准 rsync 客户端可以推送和恢复文件，WebDAV 客户端可以浏览、上传、下载和管理同一份文件。

文件内容在服务端分块、去重并加密后，保存到本地目录或 WebDAV 存储。每个模块拥有独立的密钥文件、SQLite 元数据库和数据后端。

**v0.5 只保留当前状态。** 文件修改即覆盖，删除即从清单消失；CrySync 不保留历史版本。需要历史恢复时，应由上层备份工具管理版本。

```text
rsync 客户端 ──┐
              ├── CrySync ── 分块 / 去重 / 加密 ── 本地目录或 WebDAV
WebDAV 客户端 ─┘      │
                     ├── SQLite：目录树、文件属性、块映射
                     └── 密钥文件
```

## 能做什么

- **rsync 备份与恢复**：兼容协议 30/31，测试使用真实 rsync 3.4.1；支持未变化文件 quick check、备份方向 delta 增量传输、子路径恢复、`--delete` 和 `--dry-run`。
- **WebDAV 文件服务**：支持目录浏览、Range 下载、PUT、MKCOL、DELETE、COPY、MOVE；浏览器可以直接查看目录，两个前端的写入共享当前清单。
- **加密与去重**：默认 4 MiB 固定分块，SHA-256 判重，AES-256-GCM 加密。后端保存随机命名的 blob；目录树和属性在 SQLite 中明文保存。
- **灵活存储**：本地目录或 HTTP/HTTPS WebDAV 后端；两种后端都按逻辑 blob 名的 SHA-256 前缀进行默认两级分桶（可配置 1～4 级），并支持模块级上传并发上限和进程级在途块内存上限。
- **Meta 灾难恢复**：本地 SQLite 仍承担在线读写；服务默认每小时把一致快照分片加密到后端 `meta/`，保留 24 版。仅剩 key 时会恢复最新完整版本并校验全部引用数据。
- **部署**：纯 Go 静态二进制、Docker；发布工作流构建 Linux amd64 和 arm64 产物。

## 使用边界

- rsync 会话逐文件更新；中途失败时，已落库文件保留，整个会话不会回滚。重试可继续同步。
- WebDAV LOCK/UNLOCK 为无状态兼容实现，不提供客户端独占锁。目录 MOVE/DELETE 逐条更新，整个目录操作没有单事务保证。
- 加密保护后端文件内容；服务端能接触明文、密钥和元数据。网络传输不会因存储加密而自动加密：WebDAV 前端使用 HTTP，可通过 TLS 反向代理提供 HTTPS；rsync daemon 需部署在可信网络或受保护的隧道中。
- 认证用户表按前端配置，没有按用户隔离模块或独立授权的能力。`read_only` 按模块生效。
- rsync 压缩、追加及恢复方向 `--atimes` 会被拒绝；xattr、硬链接和稀疏文件传输尚未实现。设备和特殊文件备份时跳过并记录警告。
- 核心已有 GC 方法，但当前 CLI 和 daemon 均未接入回收入口；覆盖、删除或失败写入留下的孤儿 blob 不会自动清理。
- v0.4.x 快照数据库无法直接打开，也没有迁移命令。升级应保留旧数据及可读它的旧环境，在独立的新仓库重新备份并验证。
- blob 物理布局使用 `ab/cd/<blobName>` 分桶，`ab/cd` 来自 SHA-256(blobName)。分桶不能关闭，旧平铺布局不读取或迁移；升级前应保留旧数据并在新仓库重新备份。
- key 不会上传到数据后端，必须独立备份。只有 key、本地 Meta 缺失且远端没有有效 Meta 备份时，模块会拒绝启动，不再静默创建空仓库。

更详细的运行行为和排障见[使用与部署](docs/usage.md#运行与排障)。
